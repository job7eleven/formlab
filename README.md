# 動作實驗室 FormLab V2.1

更新日期：2026-10-10
前身：跑姿記錄器 v1 和 v2（`runform_v1`、`runform_v2` 都保留不動）

## 1. V2.1 變更摘要

| 項目 | 內容 |
|---|---|
| 名稱 | 跑姿記錄器 → **動作實驗室 FormLab** |
| 運動項目 | 開啟 App 時先問「今天要記錄什麼動作？」，可選：**跑步／引體向上／棒球打擊**。App 會記住上次的選擇，之後可從下方按鈕隨時切換 |
| 版面 | 拍攝畫面優先：攝影畫面佔大部分螢幕，正下方固定一排「項目｜⚙ 設定｜● 開始」；設定改成點了才展開的面板；回放和已存紀錄移到「紀錄」分頁 |
| 記錄中的畫面 | 不顯示即時指標，只顯示**偵測燈號**、**大字倒數**和 fps；輔助線在記錄時自動隱藏 |
| 記錄後 | 自動切到「本次紀錄概要」並開啟回放 |
| 各項目的記憶設定 | 等待時間、記錄時長、模型、提示音依項目分開記住。預設值：跑步 1 分／2 分，引體向上和打擊 10 秒／1 分 |
| 圖示 | 跑步火柴人的手臂改成從肩膀長出 |
| 匯出 | **同名 CSV + JSON** 兩個檔案，存到手機「下載」資料夾 |
| 分析範圍 | 跑步：完整分析（沿用 v2）。引體向上、棒球打擊：V2.1 只記錄骨架；回放可用，次數和動作分析留待後續版本 |

> 第一次同時存兩個檔時，Android Chrome 會詢問是否允許下載多個檔案，請按「允許」。

## 2. 通用資料格式（schema：`formlab-1`）

檔名格式：`formlab_<項目>_<YYYYMMDD_HHMMSS>.csv` 和 `.json`
項目代碼：`run`＝跑步、`pullup`＝引體向上、`bat`＝棒球打擊

### CSV 分三層

**第 1 層：共通層**（所有項目都有）

| 欄位 | 說明 |
|---|---|
| `schema` | 格式版本，目前是 `formlab-1` |
| `sport` | 項目代碼 |
| `session_id` | 這次紀錄的代號 |
| `frame` | 第幾格（從 0 開始） |
| `t_s` | 從記錄開始算起的秒數 |
| `t_epoch_ms` | Unix 毫秒時間（UTC），跟其他 App 對時用這欄 |
| `t_local` | 當地時間，ISO 8601 格式並附時區（例如 +08:00） |
| `valid` | 這一格有沒有抓到人：1＝有，0＝沒有 |
| `<點位>_x`、`_y` | 在畫面中的比例位置（0–1，左上角為原點，未鏡射） |
| `<點位>_z` | 相對深度 |
| `<點位>_vis` | 可信度（0–1） |
| `<點位>_wx`、`_wy`、`_wz` | 以髖部為原點的 3D 座標（公尺） |

點位：MediaPipe 的**全部 33 點**。v2 只存 19 點，V2.1 加回臉部、手指等點位，讓打擊的握棒、引體向上的下巴都能分析。

**第 2 層：事件層**（各項目共用同一組欄名）

| 欄位 | 說明 |
|---|---|
| `event` | 這一格發生的事件。跑步：`strike_L/R`（觸地）、`mid_L/R`（支撐中期）、`off_L/R`（離地）。之後引體向上會用 `top`/`bottom`，打擊會用 `swing_start`/`contact` 等 |
| `unit_n` | 第幾個動作單位（第幾步／第幾下／第幾揮） |
| `unit_side` | 左或右 |
| `unit_quality` | 這筆的品質（`ok`、`far`、`weak`、`outlier`） |

**第 3 層：項目專屬層**（欄名加項目前綴）

| 項目 | 欄位 |
|---|---|
| 跑步 `run_*` | `run_pelvis_y_cm`、`run_knee_L/R_deg`、`run_elbow_L/R_deg`、`run_trunk_deg`、`run_cadence_spm`、`run_knee_strike_deg`、`run_overstride_cm`、`run_vert_osc_cm`、`run_contact_ms` |
| 引體向上 `pull_*`、打擊 `bat_*` | V2.1 尚無，後續版本加入 |

### JSON（給分析時快速讀取）

| 欄位 | 內容 |
|---|---|
| 基本資訊 | `schema`、`app`、`version`、`sport`、`session_id` |
| 時間 | `start_epoch_ms`、`start_local`、`timezone`、`duration_s`、`frames`、`avg_fps` |
| `settings` | 身高、模型、等待秒數、預定時長、是否提前結束、前或後鏡頭、來源（攝影機或影片檔） |
| `video` | 畫面寬高 |
| `analysis` | 近側是左或右、移動方向、每像素幾公分、使用的分析方法 |
| `summary` | 本次概要。跑步包含：步頻、垂直振幅、觸地膝角、跨步距、觸地時間（含近側／遠側）、軀幹前傾、手肘角度、剔除步數 |
| `files` | 對應的 CSV 和 JSON 檔名 |
| `csv_layers` | 這份 CSV 三層各有哪些欄位 |

> 不再附 README.txt。欄位說明以本文件為準，每個 JSON 都會寫明格式版本（`schema`）。

## 3. 檔案大小

33 點的 CSV 每格約 1.75 KB：

| 記錄條件 | 大小 |
|---|---|
| 30 fps × 1 分 | ≈ 3 MB |
| 30 fps × 2 分 | ≈ 6 MB |
| 30 fps × 5 分 | ≈ 16 MB |

## 4. 測試紀錄

| 測試項目 | 結果 |
|---|---|
| 歡迎畫面、選項目、拍攝畫面、設定面板 | 正常（模擬攝影機） |
| 用 10/10 實測數據灌入「跑步」 | 概要、回放、匯出 CSV＋JSON 正常；數值與 v2 一致（步頻 177、觸地膝角 149°、跨步距 17 cm） |
| 同一份數據灌入「引體向上」 | 只記錄模式的概要與回放正常 |
| 尚未在實機驗證 | fps、傾斜儀、前鏡頭、提示音、兩個檔案同時下載 |

## 5. 後續版本

- **V2.2**：引體向上分析（次數、動作幅度、節奏、擺盪），加入每完成一下的提示音，以及「靜止 5 秒自動結束」。
- **V2.3**：棒球打擊分析（自動切出每一揮、手腕速度、肩髖旋轉時間差、頭部位移），以慢動作影片模式為主。
- **V3**：讀入目標設定檔（goals.json），標示每項數值是否達標；另做 Cowork Skill 產出分析報告。
