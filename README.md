# 動作實驗室 FormLab V3

更新日期：2026-10-11
前一版：`formlab_V2.1`（保留）

## 1. 運作架構

```
① Gemini 看教學影片 ──▶ goals_xxx.json（目標數值＝資料）
② Claude 審核目標 ──▶ 新指標加進 App 指標庫（計算方法＝程式）
   └ goals JSON 上傳到 GitHub 儲存庫的 goals/ 資料夾，App 自動讀取
③ 使用者選「項目 → 本次目標」→ 記錄 ──▶ 動作紀錄封包 ZIP
④ 分析工具（LLM）讀封包 ──▶ 成果與改善建議報告（Cowork Skill 之後再做）
```

分工原則：**App 負責算出數字，LLM 負責解讀與建議**。LLM 直接使用 App 算出的數字，不重新計算，報告的數字才會前後一致。

## 2. V3 變更摘要

| 項目 | 內容 |
|---|---|
| 運動項目 | 跑步、引體向上、棒球打擊，新增**舞蹈**、**未定義（高解析）**、**未定義（低解析）**；選「未定義」時要輸入動作名稱 |
| 本次目標 | 選完項目後接著選目標檔，只列出同一項目的目標，也可選「不比對目標」。App 會記住每個項目上次選的目標 |

| 封包 | **一個 ZIP**，內含 `record.json`、`README.md`、`goals.json`、`data.csv`；以 deflate 壓縮；保留 3D 座標；小數 3 位 |
| 輕量判讀 | 記錄後依目標逐項顯示：達進階／達入門／未達／無數據／App 未支援，並附「逐步或逐下的達標比例」 |

| 傳送 | 「分享…」可透過 Android 分享選單傳到 Google Drive App 並選資料夾；或設定 Google OAuth 後，直接上傳到 Drive 指定資料夾 |
| 全螢幕 | 拍攝畫面右上角按鈕，可進入／退出全螢幕 |
| 記錄者 | 設定中可填寫記錄者名稱，會寫進封包 |

## 3. 各項目預設

| 項目 | 代碼 | 點位數 | 記錄 fps | 球棒 | App 分析 |
|---|---|---|---|---|---|
| 跑步 | `run` | 21 | 30 | － | 完整（步伐、觸地／離地、9 項指標） |

## 4. 動作紀錄封包（ZIP）

| 檔案 | 內容 |
|---|---|
| `record.json` | **分析時先讀這份**，內容如下：<br>`session`：項目、記錄者、時間、fps<br>`settings`：點位清單、是否含 3D<br>`quality`：有效畫面比例、近側、移動方向<br>`summary`：本次統計<br>`units`：每一步或每一下的明細表<br>`goal_evaluation`：逐項和目標比對的結果<br>`csv_columns`：CSV 欄位說明 |
| `goals.json` | 記錄當下使用的目標檔副本（有選目標時才有） |
| `README.md` | 給分析工具的固定說明：各檔案用途、欄位意義、判讀原則、建議的報告結構 |
| `data.csv` | 每一格的骨架數據（schema `formlab-2`），分四層：<br>共通層：時間、有效與否<br>事件層：步伐或次數事件<br>項目層：`run_*`、`pullup_*`<br>點位層：每個點位有 x、y、z、可信度、3D 座標共 7 個值<br>棒球打擊另有球棒層：`bat_knob_x/y`、`bat_tip_x/y`、`bat_score` |

`goal_evaluation` 的判定結果（`status`）：

| 值 | 意思 |
|---|---|
| `advanced_met` | 達進階目標 |
| `beginner_met` | 達入門目標 |
| `not_met` | 未達標 |
| `no_data` | 本次沒有做到這個動作，或偵測不足 |
| `unsupported` | App 尚未支援這個指標；若指標是角度，會另附整段的角度分布 `generic_angle_stats`，供 LLM 參考 |

## 6. 目標檔放到 GitHub（一次設定）

1. 到 GitHub 的 `runform` 儲存庫，按「Add file → Create new file」，在檔名欄輸入 `goals/README.md`，內容隨便寫一行，按「Commit」。這樣就建好 `goals` 資料夾了。
2. 進入 `goals` 資料夾，按「Add file → Upload files」，把電腦上 `goals\` 資料夾裡的目標 JSON 拖進去，按「Commit」。
3. App 會透過 GitHub 公開 API 自動找到資料夾裡所有 `.json` 檔，並依檔案內的 `sport` 欄位分配到各項目。
   - 讀到的結果會暫存 6 小時。
   - 剛上傳的新檔案，在選目標的畫面按「重新載入」即可立刻讀到。
4. 備用方式：如果自動讀取失敗，可在 `goals/` 放一個 `index.json`，內容是檔名清單，例如 `["goals_引體向上_Muscle Up.json"]`。

## 7. 直接上傳 Google Drive（選用，約 15 分鐘）

不做這項設定也可以：在紀錄裡按「分享…」，選 Google Drive App，再選擇資料夾即可。
要讓 App 直接上傳到固定資料夾，需要先建立 Google OAuth 用戶端：

1. 到 console.cloud.google.com，建立一個專案，例如命名為 `FormLab`。
2. 到「API 和服務 → 程式庫」，搜尋並**啟用 Google Drive API**。
3. 到「OAuth 同意畫面」：
   - 使用者類型選「外部」，填寫應用程式名稱和支援信箱。
   - 在「測試使用者」加入你自己的 Google 帳號。
4. 到「憑證 → 建立憑證 → OAuth 用戶端 ID」：
   - 應用程式類型選「網頁應用程式」。
   - 「已授權的 JavaScript 來源」填 `https://<你的帳號>.github.io`。
5. 複製產生的「用戶端 ID」，貼到 App 的「設定 → Google Drive → OAuth 用戶端 ID」，再按「登入 Google 並測試」。

使用上要注意：
- App 只要求 `drive.file` 權限，只能存取它自己建立的檔案和資料夾，看不到你雲端硬碟裡的其他檔案。
- 封包會上傳到 App 在 Drive 建立的「FormLab 紀錄」資料夾（名稱可在設定中修改）。
- 想讓檔案自動同步到電腦：在電腦安裝「Google 雲端硬碟」桌面版即可。
- 登入大約維持 1 小時，過期後再按一次上傳就會重新登入。
- 「記錄後自動上傳」只在登入有效時運作。

## 9. 已知限制

- 球棒偵測是從「偵測框的對角線」推估握把端和棒頭端。快速揮棒時常偵測不到，建議用慢動作影片模式。
- 引體向上的 Muscle Up 相關指標都是近似算法，需要真人實測後校正。
- 從側面拍攝時，「雙肘過槓時差」裡遠側手肘的數據不可靠，Gemini 的目標檔本身也建議改從 45° 角拍攝。
- V2.1 存在手機裡的紀錄不會出現在 V3 的紀錄清單（V3 的資料格式不同）。
